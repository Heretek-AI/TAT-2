## 4. Trajectory A/B (three arms, one process, 240 frames each)

Metric: **max per-frame planar deviation (m)** of a guard's `(x,z)` from the
`off` trajectory at the same frame index. Arena: a 4-point 4×4 m patrol square,
live physics floor, no player.

| pair | tolerance | measured |
|---|---|---|
| off vs shadow (signature) | identical ≤ 1e-9 m | `dev_off_shadow = 0.000000000` (both FSM digests `-5750684789768048477`) |
| patrol+writer vs off | different ≥ 0.05 m | `dev_patrol = 0.255` |
| patrol+writer vs off | bounded ≤ 5.657 m (the 4×4 m arena's diagonal `sqrt(32)`; any two points on the same loop are at most the diagonal apart) | `dev_patrol = 0.255` |
| writer step | ≤ `patrol_speed/60 × 1.5 + 0.01` = 0.0419 m | `writer_step_max = 0.0213` m |

Writer activity in the 240-frame arm: `moves=221 advances=2 holds=18
path_m=4.696`, `wp_index` 0→2, trace rows 121, 21 interpreter transitions. The
difference is explained by what the spike deliberately does not do: it starts
moving only once the interpreter selects `ST_Patrol` (a few frames late), it
applies no authored `WaitSeconds` dwell and no authored facing yaw. The writer
never leaves the arena (every recorded position inside ±5 m); the A/B bounded
tolerance is tightened to the actual 4×4 m diagonal (5.657 m), not round 1's
loose 6.0 m.

The writer's `apply_step(dt)` reads only `interpreter.current_tree()`,
`interpreter.current_state_name()` and `bindings.observed`; it holds and counts
`blocked_non_neutral` on any non-NEUTRAL alertness, so no combat/search/focus
movement is faked.

## 5. Live authored event (1 of 17)

`StateTreeEvent.StimChange` is pushed by `guard_ai._hear()` after a real
`NoiseBus` record passes the authored heard-by / query-mask / radius / occlusion
filters (before the `guard_alert` early return and before the reaction-role cap:
the stim changed for this listener even if it takes the Standby role).
**The mapping is a PORT INFERENCE, not authored data**: the cook serialises only
the tag name (no value bytes for the transition gate), and nothing in the
payload states that a heard record is a `StimChange`; the inference is that an
accepted hearing record is a stimulus change for the listener. It is labelled as
such in `events.gd` and in the `guard_ai._hear` comment.

Suite 111 emits a real `NoiseBus.emit_noise(…, "footstep")` record and asserts
`events_emitted == 1`, tag `StateTreeEvent.StimChange`, `interpreter.stats.events
== 1`, and `last_heard_tag == "footstep"`. Output:
`W9P4_EVENT tag=StateTreeEvent.StimChange count=1 last_heard=footstep stats_events=1`.

A **negative control** (`W9P4_EVENT_NEG`) proves the push sits *after* the
filters: an out-of-range record (100 m > the 25 m authored hearing range) and a
record heard while `KNOCKED_OUT` both emit **nothing** (`out_of_range_events=0
ko_events=0 stats_events=0`, `last_heard_tag` stays empty). Hoisting the push
above the range/KO filters makes suite 111 fail (see the round-2 falsification
below).

Census (measured from the payload, `events.gd`; round-2 fix): **authored 17,
emitted 1, unemitted 16, enter 3, transition 89, total 92**. The 3 state-entry
gates are the `{tag, payload_struct}` shape a string-only counter drops:
`ST_InvestigateStims_Guard#Extract Reaction Role from Event`
(`StateTreeEvent.ReactionRoleChange`), `ST_Patrol#Extract distraction Event`
(`StateTreeEvent.DistractionEvent`), and
`ST_Subtree_Combat#Extract Reaction Role from Event`
(`StateTreeEvent.ReactionRoleChange`). Neither tag is new, so `authored` stays
17. Unemitted (no event bus in the port; branches remain unreachable):

```
StateTreeEvent.AbandonLockdown, StateTreeEvent.Civilian.Flee,
StateTreeEvent.ClueChange, StateTreeEvent.ConversationEvent,
StateTreeEvent.ConversationEvent.Response, StateTreeEvent.DistractionEvent,
StateTreeEvent.GameplayTagChange, StateTreeEvent.LockdownEvent,
StateTreeEvent.LockdownGuardLeaving, StateTreeEvent.LockdownHoldPosition,
StateTreeEvent.LockdownNewAlarmGuard, StateTreeEvent.ReactionEventEnd,
StateTreeEvent.ReactionRoleChange, StateTreeEvent.SharePartnerLost,
StateTreeEvent.ShareTarget, StateTreeEvent.TargetChange
```

No parameter bag is invented: the payload serialises the tag only, and the
pushed `payload` dictionary carries the already-measured `heard_tag` /
`stim_tag` for the trace.

**Round-2 falsifications (each reverted):**

- hoisting the `push_event` to the top of `_hear()` (a promiscuous emitter
  before the filters) → suite 111 fails the out-of-range/KO assertions.
- the round-1 string-only census rule → suite 110's raw-payload negative control
  fails (`a string-only counter is wrong (89 != 92)`).
