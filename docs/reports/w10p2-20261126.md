## Collision classification contract

`AuthoredCollision.resolve()` keeps its five `source` values and adds:

- `class`: `elements` (authored simple geometry), `complex` (render-trimesh
  fallback), `no_collision` (authored `NoCollision`), `no_record` (package has no
  BodySetup dump), `absent` (no dump at all — `/Game/Test/` only, heuristic).
- `reason`: `default_complex_fallback`, `complex_as_simple_flag`,
  `explicit_no_collision`, `simple_as_complex_without_shapes`,
  `record_complex_flag`, `empty_element_record`, `no_body_setup`, `no_dump`.

Loader counters: `col_authored_elements`, `col_authored_complex`,
`col_no_record` (and `col_no_collision` still counts both authored-none and
no-record). `AUTHORED_COLLISION` prints `authored_elements=` /
`complex=` / `no_record=` alongside the old `hull=` total. The probe asserts
`elements + complex + no_collision == authored` and
`authored + absent == placed_meshes`.

**What stops being solid** (the measured class, named so a playtest can check
it): skybox buildings and mountains (`SM_DistantBuildingC` is 555 instances in
Guildhall alone, `SM_DistantTowerA/B`, `SM_Mountain*_Grass`), the tarps
(`SM_TarpFloorA..E`), cobwebs (`Cobweb_Web*`), the street-lamp glass
(`SM_LightStreetA`), the turret bulb (`SM_TurretBulb`, 458 + 494 instances) and
the emissive donut shell (`SM_DonutShell`). Every one of them authors
`CollisionEnabled::NoCollision`; the previous port gave them a solid render
trimesh. No floor, stair, wall, door or container mesh is in this class (the
runtime `no_record` count is 0 on all three maps).

**Gate floor.** The per-map floor changed from `0.95` on
`authored_hull / placed_meshes` (0.976321 measured) to `0.868` on
`authored_elements / placed_meshes` (0.868852 measured, FTUE). This is a
**metric correction**, not a relaxation of the same number: the old ratio
counted the render-trimesh fallback as authored collision. The old value is
still printed as `coverage=` on `COL_AUDIT`/`COL_ASSERT`, and the new one as
`element_coverage=`.

## GC gap — `GC_ChestTrunkALid`

The brief asked for the collection to be dumped, its `AutoInstanceMeshes`
resolved and the labelled chest fallback dropped. Measured outcome: that would
be **wrong**.

- The asset exists in the shipped pak (`TAT/Content/Destructibles/
  GeometryCollections/GC_ChestTrunkALid.uasset`, 1,223,508 B + `.ubulk`), but
  `extracted/json/Destructibles/` does not exist in the shared tree. A filtered
  `json` pass (with the usmap) dumps it cleanly, so **no extractor root change is
  needed** — `json` already walks every `TAT/**` package; the existing tree was
  simply produced before that pass covered the folder.
- The authored `AutoInstanceMeshes` is a single entry, `SM_ChestTrunkALid`
  (`NumInstances: 51`) — the collection's **intact** auto-instance mesh, not a
  fracture. Binding it as the broken overlay would make a smashed chest render
  as an intact lid.
- The shipped broken mesh `SM_ChestTrunkALid_Broken` is real authored art
  (`mesh_materials.json` → `MI_ChestTrunkMid`), so the current
  `_GC_BROKEN_FALLBACKS` entry is art-faithful and stays, counted as
  `fallback_broken=93`.
- New guard in `tools/parse_tables.py`: when `AutoInstanceMeshes` equals the
  owning component's intact mesh, it is skipped (`_gc_auto_instance_mesh(rest,
  intact_stem)`), so adding the dump later cannot silently introduce that
  regression; the fallback still wins.

Open item for the integrator: land `extracted/json/Destructibles/**` (one
filtered `json` pass, or a full `make extract` json stage) and re-run
`normalize`. With the guard in place the GC census is expected to stay
`fallback_broken=93`; that expectation is **not measured** in-tree yet.
