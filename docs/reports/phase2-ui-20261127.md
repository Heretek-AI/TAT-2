**Why the selection is `derived-approx`, not authored.** The extracted
`BPUI_UniversalStealthBall` records `NumTexturesInArray = 21`,
`MI_StealthBallTextureArray` → `M_TextureArray` with `TexArray` + scalar
`Index` (default 8.0), and `SetStealthValue` writes one scalar. The native
`TATUnifiedStealthWidget` code that chooses the index is **not** in the dump,
so there is no authored index→direction table to copy. The producer measures
it from the pixels; `mapping.kind` records what the payload actually is. The
HUD reports `authored_array` only when all 21 slices bind, otherwise the
existing `PORT_APPROX` fallback stays.

**Recorded port decisions and approximations** (all written down, none silent):

- `mapping.selection = {kind: "derived-approx", angle_weight: 0.35,
  source: "port_decision"}` in the producer output. The HUD reads
  `angle_weight` from the manifest and falls back to `GEM_SLICE_ANGLE_WEIGHT`
  only for a synthetic/older manifest.
- Filtering is `filter_linear` **without mipmaps**: the authored array carries a
  single mip (`Mips[0].SizeZ = 21`, `FirstMipToSerialize = 0`), so generating
  mips would add data the payload does not contain. `filter_linear_mipmap` does
  compile on a `Texture2DArray` (scratch check) but is deliberately unused.
- `MI_StealthBallTextureArray` is `BLEND_TranslucentGreyTransmittance`; the
  canvas shader composites with plain straight alpha. The array pixels
  themselves are exact, the blend model is an approximation.
- Luma is **Rec. 709** (0.2126R + 0.7152G + 0.0722B) in the producer and the
  pixel scorer; neither is ITU-R 601.

**Mapping evidence in this lane:** the derivation is proven on synthetic caps
with known angles (≤ 1.5° error) by `tools/test_stealthball_array.py` (22/22).

## 8. Capture harness fix (GPU round 3)

The GPU lane's first run at `18d1fa7` found 10 sidecars truncated **before** the
`roi.*` lines, leaving contract_table/wardrobe/ledger/ledger_market and the
briefing fit unmeasured. Root cause: `_save()` iterated
`for line: String in extras`, and five callers passed
`[_hud_sidecar(hud), "pose=…"]` — an **Array inside the extras array**. The
typed loop aborted at that element, so `side.close()` and the ROI block never
ran (5 shots × 2 sizes = 10 truncated sidecars).

Fix (harness only; no game code or pixel thresholds changed):

- the five callers are flat concatenations:
  `_hud_sidecar(hud) + ["pose=…"]` (wardrobe, ledger, ledger_market,
  contract_table, briefing);
- the writer is hardened to
  `for line in extras: side.store_line(str(line))`, so a future nested entry is
  written as one line instead of aborting the sidecar before `roi.*`;
- `grep '\[_hud_sidecar'` over the harness returns no match — every extras list
  is now a flat String list.

Proof: the captured sidecars for `contract_table` and `briefing` (both sizes)
contain the `roi.*` lines, and the ledger/wardrobe frames the same; the run
evidence is under `docs/reports/logs/phase2-ui/<run_id>/`.
